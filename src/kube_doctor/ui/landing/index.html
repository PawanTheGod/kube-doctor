Capabilities

Everything in the box, nothing invented

Screenshot investigation

Extract visible pod states, events, error messages, and metric trends from kubectl output, dashboards, and consoles.

Log-assisted diagnosis

Combine your logs with screenshot observations. Secrets in log text are redacted before any model call.

Evidence-backed findings

Every ranked cause cites verbatim evidence from your input — never an unexplained AI conclusion.

Actionable next steps

Investigative recommendations with commands classified read-only or mutating, read-only first.

Safety-first workflow

No cluster connection, no command execution. Unsafe suggestions are withheld, not silently dropped.

Flexible backends

Gemma through the Gemini API by default, or any OpenAI-compatible vision endpoint. Models are configured, never hardcoded.

How it works

Two stages, one report

  1. 01

    Provide evidence

    Upload a screenshot and optionally add logs, a namespace, or context about what changed.

  2. 02

    Analyze observations

    Stage one transcribes what is visible. Stage two reasons from those observations, your logs, and a failure-mode reference.

  3. 03

    Understand the next step

    Review the summary, ranked causes with evidence, recommended investigations, and missing information.

Safety

Read-only is the architecture, not a setting

  • Never connects to a live Kubernetes cluster — there is no cluster client in the codebase.
  • Never executes suggested commands — they are strings, linted, labeled, and printed.
  • Log text is redacted for tokens, keys, and secrets before any model call.
  • Screenshot pixels are not redacted — scrub images before uploading.
  • Uncertain cases return unknown with follow-ups instead of a guess.
  • Review anything marked mutating before running it yourself.
You→Screenshot + logs→Diagnosis
⛔ No path to your cluster. No command execution.
